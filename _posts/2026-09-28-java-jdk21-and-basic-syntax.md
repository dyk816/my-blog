Java 공부를 시작하면서 첫날 배운 내용을 정리해봤어요. JDK 설치부터 자바 코드가 실제로 실행되는 원리, 그리고 변수·형변환·연산자 같은 기본 문법까지 다뤘습니다.

## 1. JDK란 무엇인가

JDK(Java Development Kit)는 자바로 개발하고 실행하는 데 필요한 모든 것을 담은 꾸러미예요. 포함 관계로 보면 이렇습니다.

```
JDK ⊃ JRE ⊃ JVM
```

- **JVM**: 클래스 로더, 바이트코드 검증기, 실행 엔진, 메모리 관리를 담당
- **JRE**: JVM + 표준 라이브러리(java.lang, java.util, java.io 등)
- **JDK**: JRE + 개발 도구(javac, java, jshell, javap, jar, javadoc 등)

그래서 개발할 때는 **JDK 하나만 설치**하면 JRE와 JVM이 모두 딸려 옵니다.

## 2. 왜 하필 JDK 21인가

자바는 6개월마다(3월/9월) 새 버전이 나오고, 그중 일부가 **LTS**(장기 지원) 버전으로 지정돼요. LTS 버전은 8, 11, 17, **21**, 25입니다.

21을 선택한 이유는 다음과 같아요.

| 이유 | 설명 |
|---|---|
| LTS | 보안 업데이트가 오래 지원됨 |
| 호환성 | Spring Boot가 Java 17 이상을 요구하는데, 21이 충분히 충족 |
| 안정성 | 자료와 라이브러리가 충분히 검증된 버전 |

자바의 원본은 **OpenJDK**(오픈소스)이고, 이를 바탕으로 여러 배포판이 존재해요. 이번 수업에서는 Eclipse Temurin을 사용했고, 그 외에도 Oracle JDK, Amazon Corretto, Microsoft Build of OpenJDK 등이 있습니다.

## 3. JDK 21 설치 (Windows)

1. Temurin 21 설치 파일 다운로드
2. 설치 옵션 선택 (Add to PATH, JAVA_HOME 설정 등 체크)
3. PowerShell 새로 열기
4. 설치 확인

```powershell
java -version
javac -version
echo $env:JAVA_HOME
```

설치가 잘 됐다면 모두 21 버전이 확인돼요.

- **PATH**: 명령어를 찾는 폴더 목록으로, `java`나 `javac`를 어디서든 실행할 수 있게 해줘요.
- **JAVA_HOME**: JDK 설치 폴더 주소로, IntelliJ나 Gradle 같은 도구가 이 값을 참조해요.

## 4. 자바 코드의 실행 원리

자바 코드는 **두 번 번역**을 거쳐 실행돼요.

```mermaid
flowchart LR
    A["Hello.java (소스코드)"] -->|"javac (컴파일, 개발자가 한 번)"| B["Hello.class (바이트코드)"]
    B -->|"JVM (런타임, 실행할 때마다 통역)"| C["기계어"]
    C --> D["CPU 실행"]
```

- **컴파일 타임**: `javac`가 `.java` 파일을 `.class`(바이트코드)로 번역해요. 개발자가 한 번만 수행하면 됩니다.
- **런타임**: 실행할 때마다 JVM이 바이트코드를 그 컴퓨터의 기계어로 통역해요.
- **JIT 컴파일러**: 자주 반복되는 코드는 기계어로 미리 번역해두어서 실행 속도를 높여줍니다.

이 구조 덕분에 자바는 **"Write Once, Run Anywhere"**가 가능해요. 바이트코드는 특정 CPU를 위한 게 아니라 JVM을 위한 명령어라서, 같은 `.class` 파일을 Windows/Mac/Linux 어디서나 실행할 수 있습니다. (단, 각 OS에 맞는 JVM은 설치되어 있어야 해요.)

## 5. 실습: Hello.java 작성과 실행

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

지켜야 할 규칙은 두 가지예요.

- 파일 이름과 클래스 이름이 대소문자까지 정확히 일치해야 함
- 문장 끝에 세미콜론(`;`)을 붙여야 함

실행 흐름은 이렇습니다.

```powershell
javac Hello.java   # 컴파일 (성공하면 별도 메시지 없음, Hello.class 생성)
java Hello          # 실행 (확장자 없이!)
```

자주 나는 에러는 클래스명과 파일명 불일치, 세미콜론 누락, 확장자를 붙여서 실행하는 경우예요.

> 보너스로, `java Hello.java`처럼 컴파일 없이 즉시 실행하거나, `jshell`로 대화형으로 실행하거나, `javap -c`로 바이트코드를 직접 확인해볼 수도 있어요.

## 6. 리터럴과 변수

**리터럴**은 값 그 자체를 말해요(정수, 실수, 문자, 문자열, 논리 등).

| 분류 | 자료형 | 크기 | 예시 |
|---|---|---|---|
| 정수 | `byte` | 1byte | `byte b = 10;` |
| | `short` | 2byte | `short s = 10;` |
| | `int` | 4byte | `int i = 10;` |
| | `long` | 8byte | `long l = 10;` |
| 실수 | `float` | 4byte | `float f = 3.14f;` (f 접미사 필수) |
| | `double` | 8byte | `double d = 3.14;` |
| 문자 | `char` | 2byte | `char ch = 'ㅎ';` (작은따옴표, 한 글자) |
| 문자열 | `String` | - | `String str = "안녕하세요!";` (큰따옴표) |
| 논리 | `boolean` | - | `boolean bl = true;` |

변수는 **선언**과 **초기화**를 구분해서 이해하면 좋아요.

```java
int num;        // 선언
num = 30;       // 초기화
int num2 = 10;  // 선언 + 초기화를 동시에
```

## 7. 사용자 입력 받기 (Scanner)

```java
import java.util.Scanner;

Scanner sc = new Scanner(System.in);
String name = sc.nextLine();
```

- `java.util.Scanner`를 **import**해서 사용해요.
- `new Scanner(System.in)`은 콘솔(키보드) 입력을 받는 객체를 생성해요.
- `sc.nextLine()`은 한 줄 입력을 문자열로 받아와요.
- `System.out.print()`(줄바꿈 없음)와 `println()`(줄바꿈 있음)을 상황에 맞게 구분해서 써야 해요.

## 8. 형변환 (Type Conversion)

형변환은 데이터 타입을 다른 타입으로 바꾸는 과정이에요. 크게 두 가지 방식이 있어요.

| 종류 | 설명 | 예시 |
|---|---|---|
| **명시적 형변환** | 개발자가 직접 타입을 지정 | `int inum = (int)dnum;` |
| **암시적(묵시적) 형변환** | 컴파일러가 자동으로 변환 | `double dnum2 = num2;` |

여기서 주의할 점은, **명시적 형변환은 데이터 손실 가능성**이 있다는 거예요. 그래서 손실 위험이 있는 변환(큰 타입 → 작은 타입)은 반드시 명시적으로 작성해야 하고, 그렇지 않으면 컴파일 에러가 발생해요.

- 예: `double`(8byte) → `int`(4byte)는 소수점이 잘려나가므로 `(int)`를 명시해야 함
- 반대로 `int` → `double`은 손실이 없어서 자동(암시적)으로 변환됨

`char`도 내부적으로는 정수로 처리돼서, `int num3 = a;`처럼 문자를 정수(아스키/유니코드 값)로 변환할 수 있어요.

## 9. 연산자

**① 산술 연산자** `+ - * / %`

`%`(모드 연산)는 나머지를 구해요. 특히 **문자열과 숫자를 `+`로 연산할 때** 주의가 필요한데, 문자열이 `+`를 만나면 반대편 피연산자를 문자열로 바꿔버려요. 예를 들어 `"안녕" + 3`은 `"안녕3"`이 됩니다.

**② 비교 연산자** `== != < > <= >=`

두 값을 비교해서 `true`/`false`를 반환해요.

**③ 논리 연산자** `&&(AND) / ||(OR) / !(NOT)`

하나 이상의 조건을 결합해 최종 참/거짓을 평가해요. 여기서 자주 나오는 개념이 **단축 평가(short-circuit evaluation)**인데, `A && B`에서 A가 거짓이면 B는 아예 평가하지 않아요. A와 B의 순서를 어떻게 배치하느냐에 따라 불필요한 연산을 줄일 수 있어서, 면접에서도 자주 나오는 질문이라고 해요.

**④ 증감 연산자** `++ / --`

전위 연산과 후위 연산의 차이를 정확히 아는 게 중요해요.

```java
int age = 20;
++age;   // 전위: 먼저 증가시킨 후 값을 사용 → age는 21이 되고, 21이 반환됨
age++;   // 후위: 먼저 값을 사용한 후 증가시킴 → 현재 값을 반환한 뒤 age가 1 증가
```

## 핵심 키워드 정리

| 용어 | 의미 |
|---|---|
| JDK | 개발+실행 전체 패키지 |
| JRE | 실행 환경 (JVM+라이브러리) |
| JVM | 자바 가상 머신, 바이트코드를 기계어로 통역 |
| javac | 자바 컴파일러 (.java → .class) |
| java | 실행기 (.class 실행) |
| 바이트코드 | JVM용 중간 언어, OS 독립적 |
| JIT | 반복 코드를 미리 기계어로 번역해두는 최적화 기법 |
| 리터럴 | 값 자체 (정수/실수/문자/문자열/논리) |
| 형변환 | 데이터 타입을 다른 타입으로 바꾸는 것 |
| 명시적/암시적 형변환 | 개발자가 직접 지정 vs 컴파일러가 자동 변환 |
| Scanner | 콘솔 입력을 받는 클래스 |
| 단축 평가 | 논리 연산에서 앞 조건만으로 결과가 정해지면 뒤는 평가 안 함 |
| 전위/후위 연산 | `++x` (먼저 증가) vs `x++` (먼저 사용) |
